# OCP Trajectory Imitation — Training Pipeline

## Purpose

Train a neural network to imitate the behaviour of the CasADi/IPOPT OCP solver.
Given the same problem description that the solver receives (start state, target
state, obstacle layout, robot parameters), the network predicts the full optimal
trajectory that IPOPT would compute — without running the solver.

This is **supervised behavioural cloning**: the network learns the mapping

```
f(x_problem) → y_trajectory
```

from the dataset of (input, OCP solution) pairs generated by
`scripts/dataset_generation/generator.py`.

## Input / output

| | Shape | Description |
|---|---|---|
| Input | `(27,)` | `[x₀,y₀,θ₀, xT,yT,θT, 5×obs(x,y,r), safety_margin, 5×robot_params]` |
| Output — controls | `(198,)` | `[v₀,ω₀, v₁,ω₁, …, v₉₈,ω₉₈]` — 99 steps × 2 |
| Output — states | `(300,)` | `[x₀,y₀,θ₀, x₁,y₁,θ₁, …, x₉₉,y₉₉,θ₉₉]` — 100 steps × 3 |

The network produces both blocks from a two-head architecture (see `model.py`).

---

## Why two output heads?

The 498 outputs are not homogeneous:
- **Controls** (198-D): physical quantities bounded by actuator limits (m/s, rad/s)
- **States** (300-D): positions (m) and headings (rad), where headings are periodic

Splitting into two heads lets us:
1. Weight control error and state error independently in the loss
2. Track the θ indices (every 3rd element of the state block) for future
   wrapped-angle loss without index arithmetic scattered across the codebase
3. Use only the control head when the model serves as an MPC warm-start
   calculator in a later phase

## Quick start

```bash
# From project root, mpc_dl conda environment

# Train with defaults (reads data/dataset.npz)
conda run -n mpc_dl python scripts/training/train.py

# Custom dataset, output directory, and hyperparameters
conda run -n mpc_dl python scripts/training/train.py \
    --dataset data/dataset4.npz \
    --checkpoint-dir checkpoints/run1 \
    --epochs 200 \
    --lr 5e-4 \
    --batch-size 512

# Resume a previous run
conda run -n mpc_dl python scripts/training/train.py \
    --checkpoint-dir checkpoints/run1 \
    --resume

# Evaluate a trained checkpoint
conda run -n mpc_dl python scripts/training/evaluate.py \
    --checkpoint checkpoints/run1/best.pt \
    --dataset data/dataset4.npz

# Evaluate and save trajectory comparison plots
conda run -n mpc_dl python scripts/training/evaluate.py \
    --checkpoint checkpoints/run1/best.pt \
    --dataset data/dataset4.npz \
    --plot-samples 16 \
    --plot-dir results/run1/
```

## Extending the loss (future)

`loss.py` documents the θ indices and has a placeholder for replacing the MSE
on heading outputs with the geodesic (wrapped) angular error:

```
Δθ_wrapped = atan2(sin(θ_pred − θ_true), cos(θ_pred − θ_true))
```

This is the same formulation used in `Ocp.cpp` and avoids penalising
equivalent headings differently.
